# Security policy

## Supported versions

The hosted web app is deployed continuously from `main`, so the version you are
using is the current one. The standalone desktop build has no published release
yet; when it does, only the latest published release will be supported, with
fixes landing on `main` and going out in the next release.

## Reporting a vulnerability

**Please do not open a public issue.**

Report it privately through GitHub:
**[Report a vulnerability](https://github.com/kollektiv-mc/Kommands/security/advisories/new)**.

That opens a private thread visible only to the maintainers, where a fix can be
worked out before anything is public. Helpful to include, as far as you have it:
what an attacker can achieve, the build and browser or platform you saw it on,
and the steps to reproduce it. A proof of concept is welcome but not required.

This is a small project. Expect an acknowledgement within a few days rather
than within hours, and expect to be asked questions. There is no bounty
programme, and there is no embargo policy beyond "let us fix it before you
publish it", which is asked as a courtesy rather than demanded.

## What is worth reporting

The web app runs in your browser and holds nothing but what you typed into it;
the desktop build runs locally with the full privileges of the person using it,
so "the app can write the user's files" is by design, not a finding. What
matters is anything that lets **someone other than that person** influence what
it does, or what it hands to Konnekt. Concretely:

- **The saved-commands file** (`docs/persistence.md`). The desktop build writes
  it and Konnekt reads it and can run what it holds unattended. Anything that
  lets a page, a shared link or another process write into it is in scope.
- **The localhost API** the desktop shell serves (`shell/api`, `shell/serve`).
  Anything that lets a web page in a browser on the same machine reach it is in
  scope.
- **Shared links and imported commands.** A command built from a URL or a pasted
  document should never carry more than the value tree describes.
- **Content rendered from Minecraft data.** The registries are derived from a
  pinned mcmeta tag; anything that changes what they resolve to at build time
  is in scope.

## What is out of scope

- Vulnerabilities in Minecraft itself, or in what a generated command does once
  a server runs it. A command generator emits text; what it does in game is the
  operator's call.
- Anything requiring an attacker who already has control of the machine the
  desktop build is running on.
- The absence of a hardening measure, with no described impact.
- Reports generated by a scanner with no analysis of whether the finding is
  reachable in this app.
